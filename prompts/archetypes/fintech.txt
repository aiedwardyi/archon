STRUCTURAL REQUIREMENTS
═══════════════════════════════════════

1. DARK TRADING TERMINAL MOOD
- Background must feel premium and financial, not gaming neon.
- Use emerald for gains, red for losses, restrained cyan or blue for secondary actions only.
- Numbers MUST use JetBrains Mono explicitly, with precise alignment and consistent spacing to enhance readability and a professional, data-driven feel.
- Apply a dedicated numeric class or explicit selector to every price, KPI value, delta, chart axis label, and table number. Do not rely on passive inheritance for fintech numerics.
- Typography must be crisp and legible. Use Inter for all UI text, varying weights (400, 500, 600) to establish clear hierarchy without excessive font size changes. Ensure generous line-height for readability and a professional, data-driven feel.
- Use Space Grotesk for the brand, page title, and major panel headings. The shell should clearly show a display/UI/mono hierarchy instead of collapsing into one generic font stack.
- Implement a consistent, layered depth system. Use `box-shadow` for panels and cards to create a sense of elevation, `border-radius` for soft corners, and subtle linear gradients on backgrounds or interactive elements to add dimension. Avoid flat designs; every major element should have a perceived Z-index.
- This archetype should feel more like a market terminal, brokerage, or trading workspace than a generic admin dashboard. Lean into market data density, execution cues, and price-action context.

2. TOPBAR
- Brand at left, market status + 2-3 action buttons at right.
- Include a "Live market" chip and at least one timeframe/filter control.

2B. NAVIGATION SHELL
- Include a visible left rail or compact sidebar on desktop with 4-6 finance-specific destinations such as Overview, Markets, Watchlist, Orders, Portfolio, Alerts.
- The left rail should feel like part of a trading workspace, not a generic admin sidebar. Keep it compact, dark, and information-dense.
- Fintech should still feel distinct from dashboard by making the center pane chart- and market-first, but it must retain a clear persistent workspace navigation shell.

3. TICKER ROW
- 4-6 ticker cards with symbol, price, delta, and mini sparkline.
- Values must be realistic, varied, and non-zero.
- Deltas must mix gains and losses.
- Ticker row should be obviously market-focused at first glance. Symbols, deltas, and sparklines should visually separate this archetype from a generic KPI dashboard.

4. KPI GRID
- Exactly 4 KPI cards: portfolio value, day P/L, win rate, open positions.
- Large tabular numbers, delta badges, and one supporting line per card.
- Prefer execution- and market-specific labels such as buying power, day P/L, open positions, win rate, net exposure, filled orders.

5. HERO CHART PANEL
- One large chart-first focal panel above the fold.
- Include toolbar with 1D / 1W / 1M / 1Y / ALL controls, one active.
- Chart must show a real SVG path or candlestick-like construction with 12+ points.
- Add visible buy/sell/export style controls so interactivity is obvious.

6. DATA DENSITY BELOW THE FOLD
- Asset table with 6+ rows and columns for asset, price, change, holdings, value, signal.
- Each asset row MUST include a mini sparkline SVG (30×12px or similar) showing a 7-point trend line next to the change column. This is a critical fintech differentiator.
- Watchlist or order-book style side panel.
- News/activity feed with 4+ timestamped items and source tags.
- Include at least one unmistakably fintech-specific micro-surface below the fold: order book ladder, recent trades tape, analyst sentiment strip, or watchlist with sparklines.
- The desktop right rail must feel intentional: stack at least two support modules, or split a single support surface into clearly separated watchlist/news/activity sections. Do not leave one lonely card next to the main chart.

═══════════════════════════════════════
CONTENT RULES
═══════════════════════════════════════

- ZERO-VALUE BAN: never show 0, 0%, $0, empty charts, or blank rows.
- Every number must look market-realistic: $12,482.14, +3.42%, 18.7 BTC, etc.
- Use mixed positive and negative deltas with clear semantic color.
- Keep emerald/green and red semantic accents restrained and premium. Avoid radioactive greens, glowing lime pills, or oversaturated CTA chips.
- At least one panel should feel elevated and premium with layered shadow, inset highlight, and a subtle glow edge.
- Include at least one explicit click target per major surface: range pills, trade button, watch action, filter chip.
- Avoid generic dashboard filler like lorem ipsum or vague metrics.
- Do not let this archetype collapse into a generic analytics dashboard with only finance labels swapped in. The composition should clearly communicate trading, investing, or market monitoring.
- Use styled initials, local assets, or inline SVG for any avatars or profile markers. Do not use remote placeholder avatar/image services.
- If you animate or refresh numbers with JavaScript, ONLY target elements that have valid numeric `data-count` or `data-price` attributes. Never include label-only KPI cards, win-rate text, or non-price values in a generic price-update loop.
- Never reset a numeric element to `$0` or `0` before deriving its formatting rules unless the animation code already captured the original formatting. Guard every numeric update with `Number.isFinite(...)` and leave the existing text untouched if parsing fails.
