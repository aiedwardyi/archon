PREMIUM QUALITY BAR

This app must feel intentionally designed, not like a starter template or quick scaffold.

Spacing and layout:
  - Use an 8px rhythm. Prefer 8, 16, 24, 32, 48, 64, 80, 96, and 120px spacing values.
  - Major publishable sections usually need 80-120px vertical spacing on desktop and 48-64px on mobile.
  - Cards should usually have 24-32px padding unless the app shell clearly needs denser treatment.
  - Use a deliberate max-width, grid, and shell structure. Avoid cramped layouts.
  - For dashboard and fintech shells, the first KPI band should arrive quickly under the header or hero control bar. Do not leave a large dead strip of empty space before the first cards.

Typography:
  - Use a purposeful heading font choice and a readable body system.
  - Headings must have clear hierarchy, not minor size shifts.
  - Labels, badges, and table headers need their own typography treatment.
  - Do not default to system-font-only UI unless the task explicitly calls for it.
  - For dashboard, fintech, editor, chat, and other tool-like shells, default to a three-lane type system: a restrained display face for brand/page titles/panel headings, a UI sans for controls and body copy, and a mono family for numeric surfaces.
  - If base.css already provides display, UI, and mono families, keep using that system instead of collapsing the app back to one generic font stack.
  - For dashboard and fintech shells, the desktop page title should read at a true display scale, roughly 36-44px, not a generic 20-28px utility heading.

Color and depth:
  - Backgrounds should not be a single flat hex with no depth.
  - Use layered surfaces, subtle gradients, tint shifts, or glows where appropriate.
  - Establish at least three surface levels: page, card, elevated/active.
  - Use the accent color sparingly and intentionally.

Section flow and polish:
  - Publishable surfaces should have deliberate background rhythm, separators, or overlaps between major sections.
  - Reuse one radius family and one shadow family so the UI feels cohesive.
  - Add small polish details where they fit: custom selection color, strong focus rings, pill badges, avatar treatments, decorative quotes, accent bars, subtle scrollbar styling.
  - Motion should be restrained but visible: reveal choreography, hover lifts, active states, count-ups, and panel transitions.
  - Above-the-fold content must be visible on first paint. Never hide the primary shell, hero, KPI row, or first viewport content behind JS-only reveal logic.
  - Use concrete flow devices instead of vague polish: alternating surface tones, overlap cards, subtle dividers, sticky sub-bars, or section-specific accent threading.
  - Product and portfolio surfaces should avoid repeating the same centered block over and over; introduce at least one asymmetry, split layout, or editorial break in the lower half of the page.
  - Tool-like shells need composition too: one clear hero data surface, one dense KPI band, and a desktop support rail with at least two stacked secondary modules or one split module plus an activity/watch surface. Do not leave one lonely side card floating next to a giant chart.

Content authenticity and data completeness:
  - Real seeded content is mandatory. Product names, metrics, people, dates, prices, categories, and microcopy must fit the domain.
  - Domain labels must be specific, not generic placeholders.
  - For dashboard and fintech shells, reject template copy such as `Dashboard Overview`, `Portfolio Overview`, repeated `View` / `Details` row actions, and thin generic `Watchlist` / `Activity Feed` / `Recent Updates` rails unless the prompt explicitly asks for a market-terminal pattern.
  - Interface density must fit the archetype: dashboards need real data density, commerce needs shoppable cards, portfolios need authored identity, and games need atmosphere.
  - Charts MUST have visible SVG path data with real coordinates — NEVER an empty SVG or a chart with no lines/bars.
  - Tables MUST have at least 8 rows of realistic, varied data. NEVER render a table with 0-2 rows.
  - KPI cards MUST show non-zero, formatted values. NEVER "$0" or "0%".
  - Activity feeds MUST have 5+ entries with realistic timestamps ("2 min ago", "1 hour ago").
  - All data should feel alive and varied — different names, different values, mixed positive/negative deltas.
